# correlation.py 说明

## 一句话

选 5 个变量，两两配对共 10 对，每对用 4 种方法算相关，得到 40 个值（报告 Table 1）；再找出方法之间意见不一致的地方，画两张图解释原因（报告 Figure 1、Figure 2）。

## 怎么运行

```bash
python3 新代码/correlation.py
```

- **先运行 `preprocess.py`**，本文件读它生成的 `clean.parquet`
- 从哪个目录运行都可以
- 需要 `pandas`、`matplotlib`、`scikit-learn`、`pyarrow`

| | 文件 | 说明 |
|---|---|---|
| 输入 | `data/clean.parquet` | 25,728 行，读入后只用其中 21,251 行（见下） |
| 输出 | `outputs/correlation_matrix.csv` | Table 1，10 行 |
| 输出 | `outputs/fig_hlc_vs_y.png` | Figure 1 |
| 输出 | `outputs/fig_dsl_vs_dist.png` | Figure 2 |
| 输出 | `outputs/evidence_correlation.json` | 报告相关性部分引用的全部数字 |

代码分成 7 段，每段开头有 `# %%` 标记，可以在 VS Code 里单独运行，也对应最终 notebook 的一个 cell。变量名都用全称（比如 `listings` 是有评论的 21,251 行、`correlation_table` 是 Table 1、`host_size_bands` 是 Figure 1 的分档数据），每行后面有详细注释。

## 为什么只用 21,251 行

`clean.parquet` 有 25,728 行，其中 4,477 个房源从来没有评论。它们的"距上次评论天数"是 `preprocess.py` 人为填的 **4,594**，不是真实值。4,477 个相同的值堆在最右端，会把相关系数拉偏。

所以读入后先筛掉，只留 `has_review == 1` 的 **21,251 行**。报告里 Table 1、Figure 1、Figure 2 用的都是这 21,251 行。

## 5 个变量

| 变量 | 缩写 | 含义 | RQ 里属于 | 来源 |
|---|---|---|---|---|
| `host_listings_count` | HLC | 房东的房源数（房东自报的平台总数） | 运营（规模） | 原始数据 |
| `days_since_last_review` | DSLR | 距上次评论天数 | 运营 | preprocess 步骤 1 |
| `availability_365` | AV365 | 未来一年可订天数 | 运营 | 原始数据 |
| `dist_cbd` | DIST | 到市中心的距离 | **硬实力** | preprocess 第 5 段 |
| `y` | SH | 是不是超级房东（目标） | — | preprocess 第 1 段 |

**为什么是这几个**：RQ 问的是"硬实力 vs 运营策略"，所以两边都要有代表，再加上目标 `y`（作业要求必须包含目标）。

**为什么硬实力选距离不选价格**：价格其实是房东自己定的，更像运营决策，放进硬实力会把两边混在一起；而且价格缺了 25%，补出来的值会影响相关系数。

**为什么只选 5 个**：5 个变量是 10 对 × 4 种方法 = 40 个值，一张表放得下。6 个就是 15 对 60 个值，10 页报告放不下。

**已知不足**：运营侧 3 个、硬实力侧只有 1 个，偏了。报告里要主动承认，硬实力的完整比较留给 B 板块（用全部特征建模）。

## 4 种方法是什么

| 方法 | 测什么 | 范围 | 大白话 |
|---|---|---|---|
| **Pearson** | 线性关系 | −1 到 1 | 能不能画一条直线穿过这些点。对极端值很敏感 |
| **Spearman** | 单调关系 | −1 到 1 | 先把数据换成排名再算 Pearson。只看"X 变大时 Y 是不是一直变大（或一直变小）"，不管变得快慢。极端值只是"第一名"，影响被压小 |
| **MI**（互信息） | 任何形式的依赖 | 0 以上，没有上限 | 知道 X 之后，对 Y 的不确定性减少了多少。不管关系是直线、曲线还是先升后降都能测到 |
| **NMI**（归一化互信息） | 同上 | 0 到 1 | 把 MI 缩放到 0–1，**不同变量对之间可以比较大小** |

三者的包含关系：**线性 ⊂ 单调 ⊂ 任意依赖**。所以如果一个关系是先升后降，Pearson 和 Spearman 都会接近 0，只有 MI / NMI 能抓到。这正是本分析的核心发现。

**目标 `y` 是 0 / 1，有两点要注意**：
- Pearson 算"连续变量 vs 0/1"时有个专门的名字，叫**点二列相关（point-biserial）**。能用，报告里要点明
- Spearman 算 `y` 时，`y` 转成排名后只有两个值，等于"把 X 换成排名后再算点二列相关"，是 Pearson 的抗极端值版本，**不是重复**

**为什么不报 p 值**：21,251 行这么大的样本下，几乎任何相关系数都会"显著"。比如 HLC ~ SH 的 −0.069 实际上约等于没关系，p 值仍然远小于 0.05。所以我们看的是系数大小，不是显著性。

## 逐段讲解

### 第 0 段：准备

- 读 `clean.parquet`，筛出有评论的 21,251 行
- `CORRELATION_VARIABLES`：5 个变量，最后一个是目标 `y`
- `equal_frequency_bin`：分箱工具。MI / NMI 只能处理离散的类别，不能直接吃连续数字（比如距离有两万多个不同的小数，每个只出现一次，没法算）。所以要先把连续数字切成若干箱，变成"第几箱"
  - `y` 本来就只有 0 / 1，原样返回
  - 连续变量用 `pd.qcut` **等频**分 10 箱，每箱的房源数大致相同
  - `labels=False`：返回箱号 0、1、2……，而不是区间文字
  - `duplicates="drop"`：`availability_365` 有 21.8% 的值都是 0，同一个值没法拆进两个箱，会导致箱的边界重复。这个参数把重复的边界合并掉，代价是实际箱数少于 10（见 Table 1 的 `bins` 列）

### 第 1 段：分箱决策的证据

分箱方式是我们自己选的，报告里要用数字说明为什么这么选。这一段就是算这些数字。

**为什么等频，不等宽**

等宽分箱是把数值范围平均切开。但 `host_listings_count` 中位数只有 2、最大值 667，等宽切 10 箱时，**91.4% 的房源挤在第一个箱里**；切到 20 箱还有 **84.6%**。绝大部分房源在同一个箱，MI 根本算不出区分度。所以用等频。

**为什么 10 箱**

两个变量各 10 箱，组合出 100 个格子，21,251 行平均每格约 **212 个**房源，估计稳定。20 箱就是 400 个格子，每格只剩约 **53 个**，太稀了。

**为什么跨对比较只看 NMI**

用 DSLR ~ AV365 这一对试不同箱数：

| 箱数 | MI | NMI |
|---|---|---|
| 5 | 0.1175 | 0.0799 |
| 10 | 0.1829 | 0.0856 |
| 20 | 0.2499 | 0.0896 |
| 变化 | **+113%** | **+12%** |

同一对变量、同一份数据，只是切得细一点，MI 就翻了一倍多，NMI 基本不变。说明 **MI 的大小主要取决于分了几箱**；再加上各变量实际箱数不同（7 到 10 箱），**MI 不能跨行比较，比较强弱只看 NMI**。

另外记下的分布数字（报告 Methodology 引用）：HLC 中位数 2、75% 分位 14、最大 667；DSLR 中位数 84、最大 4,593；AV365 有 21.8% 是 0、只有 1.56% 是 365。

### 第 2 段：Table 1

5 个变量两两组合共 10 对，每对算一行：

| 列 | 含义 |
|---|---|
| `pair` | 哪两个变量 |
| `pearson` / `spearman` | 两个相关系数，保留 3 位小数 |
| `mi` / `nmi` | 互信息 / 归一化互信息，保留 4 位小数 |
| `bins` | 两个变量实际分成几箱，如 `7×10`。`y` 永远是 2 |

**按 NMI 从大到小排序**，和报告 Table 1 的顺序一致。

结果：

| 变量对 | Pearson | Spearman | MI | NMI |
|---|---|---|---|---|
| DSLR ~ AV365 | −0.438 | −0.395 | 0.1829 | 0.0856 |
| DSLR ~ SH | −0.337 | −0.443 | 0.1159 | 0.0785 |
| AV365 ~ SH | 0.146 | 0.155 | 0.0425 | 0.0324 |
| HLC ~ DIST | −0.131 | −0.225 | 0.0580 | 0.0285 |
| HLC ~ DSLR | −0.113 | −0.194 | 0.0558 | 0.0274 |
| HLC ~ AV365 | 0.059 | 0.225 | 0.0430 | 0.0230 |
| AV365 ~ DIST | 0.170 | 0.124 | 0.0315 | 0.0147 |
| DSLR ~ DIST | −0.081 | 0.061 | 0.0317 | 0.0138 |
| HLC ~ SH | −0.069 | 0.070 | 0.0117 | 0.0097 |
| DIST ~ SH | 0.076 | 0.009 | 0.0070 | 0.0047 |

怎么读：
- **预测变量之间最强**的是 DSLR ~ AV365（NMI 0.0856），四种方法方向一致：越久没评论的房源，可订天数越少，两者可能有重叠信息
- **和目标最强**的是 DSLR ~ SH（NMI 0.0785）：越久没评论，越不可能是超级房东
- **最弱**的是 DIST ~ SH，四种方法全部接近 0，NMI 全表最低：离市中心远近和是不是超级房东几乎没关系

### 第 3 段：找分歧

找 Pearson 和 Spearman 意见不一致的变量对：

- **差距最大**：HLC ~ AV365，差 0.166（0.059 vs 0.225），但方向相同
- **一正一负**（两个系数相乘小于 0）：**HLC ~ SH** 和 **DSLR ~ DIST**

一正一负的两对系数都很小（绝对值 0.06–0.08），光看数字分不清是真实规律还是零附近的随机波动。所以接下来画图确认。

### 第 4 段：Figure 1 —— 房东规模 vs 超级房东率

把房东按房源数分成 7 档（边界 1、2、5、14、50、100、700；2 是中位数，14 是 75% 分位，700 盖住最大值 667），每档算超级房东率。

| 房源数 | 房源个数 | 超级房东率 |
|---|---|---|
| 0–1 套 | 8,103 | 28.48% |
| 2 套 | 2,560 | 41.52% |
| 3–5 套 | 2,832 | **46.08%**（最高） |
| 6–14 套 | 2,481 | 40.10% |
| 15–50 套 | 2,818 | 42.73% |
| 51–100 套 | 1,198 | 41.90% |
| 超过 100 套 | 1,259 | **16.92%**（断崖） |

整体是 35.72%（图里的红色虚线）。**两头低、中间高，是倒 U 型。** 每档样本量都上千，不是小样本造成的噪音。

这解释了为什么两个系数一正一负：
- **Pearson 是负的**：超过 100 套的那 1,259 个房源的数值在 100–667 之间，远大于其他人，在原始数值上把整条线拽成了向下
- **Spearman 是正的**：换成排名后，667 只是"最后一名"，极端值的影响被压小，主体部分（0–1 套 → 3–5 套）的上升趋势占了上风
- **两个都接近 0**：上升段和下降段互相抵消
- **NMI 不为 0**：倒 U 是真实存在的关系，只是不单调，只有互信息测得到

**对 RQ 的意义**：不是"规模和超级房东无关"，而是**中等规模最高，规模太大反而最低**。只看 Pearson 或 Spearman 会得出"几乎无关"的错误结论。

**写报告时注意**：只能说"相关"，不能说"导致"。超过 100 套的房东可能主要做长租或商务公寓，客群和评价方式本来就不同，这可能才是超级房东率低的原因。

### 第 5 段：Figure 2 —— 到市中心距离 vs 距上次评论天数

按距离等频分 20 档（每档约 1,063 个房源），每档算中位距离和中位天数。用中位数，因为天数最大有 4,593，平均数会被拉偏。

| 中位距离 | 中位天数 |
|---|---|
| 0.61 km | 60 |
| 1.24 km | 41（最低） |
| 1.36 km | 51 |
| **1.71 km** | **111**（350 米内翻倍） |
| 5.04 km | 122（最高） |
| 15.15 km | 91 |
| 50.64 km | 47 |

**先升后降**：市中心 1.4 公里以内最活跃，约 1.5 公里处突然跳高，5 公里左右最不活跃，再往外又变活跃。两段方向相反，所以 Pearson 和 Spearman 都被抵消到接近 0，NMI（0.0138）仍然测到了关系。

1.5 公里处的跳变**可能**对应 CBD 核心区向周边住宅区的过渡，但这是推测，不是数据能证明的。**报告里用 "may reflect" 这类说法，不要写成确定的结论。**

## 结论汇总（写报告用）

1. **运营侧强，硬实力侧弱**：和目标的关联按 NMI 排序是 DSLR 0.0785 > AV365 0.0324 > HLC 0.0097 > DIST 0.0047。唯一的硬实力变量 DIST 全表最低，而且四种方法一致接近 0
2. **规模呈倒 U 型**：中等规模（3–5 套）超级房东率最高 46.08%，超过 100 套最低 16.92%
3. **四种方法缺一不可**：两对变量的关系是非单调的，只有 MI / NMI 能测到，Pearson / Spearman 会误判为无关
4. **限定**：变量集偏向运营侧（3:1）；DSLR 与近 12 月评论数相关 −0.8155，部分代替了被剔除的评论数；只用了有评论的房源；以上都是相关，不是因果

## 常见疑问

**为什么 MI 表里不能比大小，NMI 可以？**
MI 没有上限，而且分的箱越多数值越大。不同变量实际箱数不同，MI 直接比会失真。NMI 缩放到 0–1，受箱数影响小得多（+12% vs +113%）。

**为什么 `bins` 列里有 7 和 8，不是 10？**
HLC 和 AV365 有大量重复值（比如很多房东只有 1 套房，很多房源可订天数是 0），重复的箱边界被合并了。

**Figure 1 的整体比例为什么是 35.72%，不是 30.65%？**
30.65% 是全部 25,728 个房源的超级房东率；这里只用了有评论的 21,251 个，它们的超级房东率是 35.72%。

**报告里的数字和 json 对不上怎么办？**
以 `evidence_correlation.json` 和 `correlation_matrix.csv` 为准，改报告。
